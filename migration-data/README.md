  사용자가 캡처로 제보한 챗봇 문제와, 벤치마킹 사이트에서 착안한 데이터 관리 기능을 반영:

    있어야만 매칭되던 문제 → `눈\s*(이)?\s*(오|와|온|내리)` 형태로 조사 선택적으로 완화.
    "-면" 조건형 어미도 상관관계 질문 트리거에 추가.
  - **"브러쉬홀더 교환 어떻게해?"가 수선의뢰 등록으로 오작동하던 문제 수정**: 등록 의도
    감지 정규식의 "어" 어미가 "어떻게"의 "어"에도 걸려 오탐 — "어떻게/어케/하는법/하는방법/
    방법" 뒤에는 매칭 안 되도록 부정형 전방탐색(negative lookahead) 추가해 절차 질문과
    등록 요청을 구분.
  - **대화 도중 딴 이야기로 넘어가도 계속 이전 단계에 갇혀 응답 못 하던 문제 수정**: 위 오탐
    버그로 등록 흐름이 잘못 시작되면, 이후 어떤 질문을 해도 그 단계의 좁은 파서가 계속
    "이해 못했어요"만 반복하던 구조적 문제. 사용자가 흐름과 무관한 질문/주제 전환을 하면
    자동으로 등록 진행을 취소하고("수선의뢰 등록은 잠시 멈췄어요") 원래 질문에 정상 답변하는
    로직(`isTopicChange`/`looksLikeExpected`) 추가. 단, 이번 챗봇은 규칙(정규식) 기반이며
    지식그래프·LLM 기반 의미 이해는 아님 — 사용자가 요청한 수준의 진짜 문맥 이해는 별도의
    큰 구조 변경이 필요하다는 점을 안내함.

    tm_assets/repair_history/external_repair_log 전체를 이름 붙여 저장(`data_snapshots`
    테이블, RLS로 관리자만 접근). 복원 시 확인 다이얼로그 필수 + 복원 직전 자동으로
    "복원 전 자동 백업" 스냅샷을 먼저 생성한 뒤 덮어써 실수로 데이터를 잃지 않도록 안전장치.
    실제 다인원 공유 DB이므로 "예전 시점으로 되돌리기"가 실수 시 되돌릴 수 없는 위험이 없게
    설계.
  - **엑셀 가져오기(신규, 같은 화면)**: 기존 "데이터 내보내기" 양식과 헤더를 그대로 재사용해
    양방향 호환. 파일 업로드 → 미리보기(시트별 신규/수정/오류 건수 + 행별 문제점) →
    "반영" 버튼으로 명시적 확정하는 2단계 구조(업로드 즉시 덮어쓰지 않음). tm_assets는
    시리얼 기준 upsert, repair_history는 신규 건만 삽입. 정합성 검사 로직을 재사용해
    가져오는 데이터도 함께 교차 검증.
  - 브라우저 검증 완료(관리자 세션): 스냅샷 저장→목록에 171/128/47 표시→복원 클릭 시
    확인창→실행 후 "복원 전 자동 백업" 스냅샷 자동 생성 확인. 앱에서 내보낸
    `편성별현황_20260829.xlsx`를 그대로 업로드→미리보기 "신규 0건·수정 144건·오류 0건"→

  아직 시작 못함. Lovable 에디터 우측 상단 설정(⚙️) → GitHub 탭에서 사용자 본인이 직접
  GitHub 계정 연동을 승인해야 함(OAuth라 대행 불가). 이후 사내 서버 배정 여부를 IT팀에
  확인해야 다음 단계(백엔드 자체 호스팅, 실제 배포) 진행 가능.
- **TM 리포트 HWP 다운로드**: 브라우저에서 안정적으로 생성할 라이브러리가 마땅치 않아
  의도적으로 보류. 필요시 별도로 난이도/방법 재검토.
- **`/risk-criteria`(산출기준) 화면 재구성**: 현재 발생도 O 표 → 심각도 S 표(길다) →
  매트릭스(직관적으로 가장 이해하기 쉬운 부분) 순서라 "3단계 표가 늦게 나와서 어렵게
  느껴진다"는 피드백. 매트릭스를 먼저 보여주고 근거 표는 아래로 내리는 순서 개편 착수 전
  (초안은 마련됨, 크레딧 소진으로 대기 중).
- **대시보드 상단 메뉴 클릭 시 현재 위치 강조 안 보이는 문제**: 어떤 메뉴를 눌렀는지
  시각적으로 구분이 안 된다는 피드백. 원인 파악(활성 스타일이 기본 레이아웃 클래스와
  충돌하거나 대비가 약함) 및 수정안(`cn()`으로 클래스 병합 + 뚜렷한 강조색/밑줄)은 마련됨,
  착수 전(크레딧 소진으로 대기 중).
- **대시보드 위젯 드래그 이동/크기조절**: 요청은 접수했으나 착수 전(크레딧 소진으로 대기 중).
- **모바일/태블릿/데스크톱 반응형 전체 점검**: 요청은 접수했으나 착수 전(크레딧 소진으로 대기 중).
