    (Lovable AI 게이트웨이 사용). 챗봇이 정비 절차·규격 관련 질문(기존 규칙 기반 분기에
    안 걸리는 경우)을 감지하면 벡터 검색으로 관련 청크를 찾아 LLM에 근거로 제공, 답변과
    함께 출처(문서명·페이지) 칩을 표시하고 클릭 시 해당 페이지로 문서 뷰어가 열림.
  - **OCR 기반 문서(수선사양서/정비지침서) 출처 답변에는 "※ 스캔 문서 OCR 인식 결과입니다.
    수치·규격은 원문 페이지에서 다시 확인하세요." 주의 문구를 자동 표시** — 표준작업절차서는
    텍스트 신뢰도가 높아 이 캡션 없음.
  - 브라우저 검증 완료: 문서 3종 열람, 외부수선이력→수선사양서 연결, "브러시 교체 방법
    알려줘" 질문에 사양서·절차서 출처 + OCR 캡션이 포함된 RAG 답변 확인.

- **정비지침서 파일 접근 완전 차단 + 문서 연계 확장** — 정비지침서는 원본 스캔 양식이
  좋지 않아 "출처 인용까지만, 파일 열람·다운로드는 절대 불가" 방침으로 전환:
  - `/documents` 페이지에서 정비지침서 카드 제거(수선사양서·표준작업절차서 2개만 노출),
    원본 PDF 파일 자체를 `public/docs/`에서 삭제해 URL로도 접근 불가하게 처리.
    `reference_documents.file_accessible` 컬럼 추가, 정비지침서만 `false`.
  - RAG 챗봇 출처 표시 분리: 수선사양서/표준작업절차서는 기존처럼 클릭 가능한 칩(문서명·
    페이지, 클릭 시 뷰어로 이동), 정비지침서는 "정비지침서 N페이지 (사내 문서, 열람 불가)"
    형태의 클릭 불가 텍스트로만 표시. **RAG 검색·학습 대상에서는 제외되지 않고 3개 문서
    전부 계속 근거로 사용됨** — 표시 방식만 문서 유형별로 다름.
  - `RelatedDocs` 컴포넌트 신설, 고장코드(FC00~FC05, FC99)별 관련 절차서/사양서 페이지
    매핑(`CODE_DOCS`)을 만들어 수선의뢰 등록 폼(고장코드 자동분류 결과 옆), TM 리포트,
    취부현황판 상세 패널(`TmDetailPanel`) 3곳에 "관련 수선 절차 보기" 링크 추가.
  - 브라우저 검증: 정비지침서 PDF 파일 삭제 및 앱 전체에 링크 없음 확인, 챗봇이 정비지침서
    근거 답변 시 클릭 불가 텍스트로만 인용하는 것 확인, 사양서/절차서는 여전히 정상 열람.
