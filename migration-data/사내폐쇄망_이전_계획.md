# TM-CBM 사내 폐쇄망 이전 계획

## 목표
지금 Lovable(인터넷)에서 돌아가는 TM-CBM 앱을, 인터넷이 안 되는 서울교통공사 사내망 안에서도
똑같이 쓸 수 있게 만드는 것.

## 지금 구조
- 화면(프론트엔드): React + TanStack Start, Lovable이 자동 빌드·호스팅
- 데이터(백엔드): Lovable Cloud가 자동으로 붙여준 Supabase(Postgres + 로그인 + 파일저장)
- 즉, 코드와 DB가 전부 Lovable/Supabase 서버(인터넷)에 있음 → 폐쇄망에서는 그대로 못 씀

## 이전 방법 (4단계)

### 1단계 — 코드 꺼내오기
Lovable 프로젝트 설정에서 **GitHub 연동**을 켜면, 지금까지 만든 화면 코드 전체가
GitHub 저장소로 자동 복사됩니다(양방향 동기화). 이 저장소를 사내망 서버로 옮기면 됩니다.
→ 제가 지금 Lovable 쪽에서 GitHub 연동 켜는 것까지는 원격으로 도와드릴 수 있습니다.

### 2단계 — 데이터베이스 교체
지금 쓰는 Supabase(Lovable Cloud)는 인터넷 서비스라 폐쇄망에서 못 씁니다. 대신:
- **추천안**: Supabase를 사내 서버에 직접 설치(오픈소스, Docker로 한 번에 설치 가능).
  지금 코드가 이미 Supabase 방식으로 짜여 있어서, 접속 주소만 사내 서버로 바꾸면
  코드 수정을 거의 안 해도 됩니다.
- 대안: 그냥 사내 PostgreSQL + 직접 만든 로그인 기능으로 교체 (더 손이 많이 감).

### 3단계 — 사내 서버에 배포
- 코드를 빌드해서 사내 서버(리눅스 서버 1대, Docker 사용 권장)에 올림
- 사내 주소(예: `tm-cbm.stnet.local` 같은 내부 도메인 또는 사내 IP)로 접속
- 한 번 서버에 올려두면 이후엔 인터넷 연결 없이도 동작

### 4단계 — 데이터 옮기기
- 지금 있는 실데이터(TM자산 171건, 수선이력 128건, 외부수선이력 47건)를
  이미 만들어둔 "엑셀로 내보내기" 기능이나 SQL 덤프로 추출
- 사내 DB에 그대로 넣기 (이미 `repair_history_migration.sql` 같은 참고 스크립트 있음)

## 진행하려면 필요한 것 (사내 IT/전산팀 확인 필요)
1. 사내망에 리눅스 서버(가상서버 포함) 1대 배정 가능한지, Docker 설치가 허용되는지
2. 사내 도메인/IP 할당 방식 (예: `10.x.x.x:8080` 또는 내부 도메인)
3. 최초 1회는 Docker 이미지·npm 패키지를 인터넷에서 받아야 하므로, 그 1회만 인터넷 되는
   환경에서 준비하거나 USB로 반입하는 방식 필요

## 지금 바로 시작 가능한 부분
GitHub 연동(1단계)은 지금 크레딧으로 바로 진행 가능합니다. 나머지(2~4단계)는 사내
서버가 실제로 배정된 뒤에, 그 서버 접속 정보를 받아서 진행해야 합니다 — 제가 사내망에
직접 접속할 방법이 없기 때문입니다.
